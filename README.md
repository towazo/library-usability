# library-usability

イベント「最凶UI × ユーザー視点」用の教材サイト「まちの図書館」です（進行者向けの資料です）。
1ページだけで、本の検索・選択・貸出申し込みができます。図書館・本・利用者情報はすべて架空で、入力内容は外部へ送信しません（ブラウザのメモリ上だけで扱い、再読み込みで消えます）。

## 起動方法

```bash
npm install      # 初回のみ
npm run dev      # 開発サーバー（表示された http://localhost:5173/ を開く）
npm run build    # dist/ にビルド
npm run preview  # ビルド結果を確認
```

## 参加者向けタスク（サイトには掲載していません）

> 気になる本を1冊選び、貸出期間を確認して、中央図書館で受け取る申し込みをしてください。入力には配布された架空情報を使ってください。

## 正常に申し込める架空の入力例

| 項目 | 値 |
|---|---|
| 本 | 一覧のどれか1冊で「この本を選ぶ」を押す |
| 利用者番号 | `12345678`（半角数字8桁なら受け付けます） |
| 氏名 | 図書 花子 |
| 受取館 | 中央図書館 |

## 5つの悪い要素

| # | 内容 | 再現方法 | UIの原則 |
|---|---|---|---|
| ① | 本を選んでも反応が分からない。内部では選択されるが、ボタンの文言・色は変わらず、メッセージも出ない。別の本を選ぶとその本に置き換わる | 「この本を選ぶ」を押す | 状態の可視化（フィードバック） |
| ② | フォームに選択中の本のタイトルや貸出期間が表示されず、何を選んだかを覚えておく必要がある（完了時にはタイトルを表示する） | 本を選んでフォームを見る | 記憶より認識 |
| ③ | 必須マークや形式の説明、プレースホルダーがなく、利用者番号が「半角数字8桁」であることが事前に分からない。検証は送信時だけ | 全角数字や7桁で申し込む | エラーの予防 |
| ④ | 本が未選択、または入力に誤りがあると「申し込み内容に誤りがあります」とだけ表示される。項目ごとの説明・赤枠・自動フォーカスはない（入力値と本の選択は保持される） | 本を選ばずに、または誤った値で申し込む | エラーからの回復（原因と直し方を示す） |
| ⑤ | 「入力をクリア」が塗りつぶしの目立つボタンで、「申し込む」は控えめな枠線ボタン。クリアは確認なしで入力・エラー・完了メッセージを消し、取り消せない（本の選択と検索条件は残る） | 入力後に「入力をクリア」を押す | 視覚的な優先順位、誤操作からの回復（取り消し） |

①は「操作が反映されたか分からない」問題、②は「後から選択内容を確認できない」問題です。

## 確認状況

2026-11-17 に、本番ビルドをローカルの Chrome で自動操作して確認しました。PC（1280×800）とスマートフォン相当（375×740、タッチのエミュレーション）で各38項目、計76項目がすべて通過しています。

**確認した内容**
- `npm run build` が成功する
- 本の一覧に表紙（6冊分）と「〇〇 著」が表示される
- タイトル検索、0件時の「該当する本がありません」、検索解除
- 本を選択でき、最後に選んだ本で申し込める。検索条件を変えても選択は保持される
- 本が未選択の場合は申し込めない
- 不正な入力（全角数字、7桁、空白だけの氏名、受取館の未選択）では共通エラーだけが出て、入力内容は消えない
- `12345678`／図書 花子／中央図書館 で申し込め、フォームの下に本のタイトル・受取館・デモである旨が表示される
- 入力クリアで、利用者番号・氏名・受取館・エラー・完了メッセージが消え、本の選択と検索条件は残る
- ①〜⑤が指定どおりに再現する（選択してもボタンや一覧のHTMLと色が変わらない、など）
- キーボードだけで検索から申し込みまで操作できる
- PCとスマートフォンで操作でき、横スクロールが出ない
- 外部への通信やPOSTがなく、localStorage／sessionStorage を使っていない。JavaScriptのエラーがない

**未確認の内容**
- 実機のスマートフォン（iOS Safari／Android Chrome）での操作（Chrome のエミュレーションでのみ確認）
- Firefox・Safari・Edge での表示と操作
- スクリーンリーダーでの実際の読み上げ
